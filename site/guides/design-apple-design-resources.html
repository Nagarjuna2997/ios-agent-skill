Design-to-project workflow

Apple source / accessible Figma node
  -> inspect component variants and variables
  -> map semantic roles to project tokens
  -> preview light, dark and high-contrast assets
  -> generate Assets.xcassets with the existing CLI
  -> build in Xcode and verify Dynamic Type / VoiceOver / resizing
  1. Open the exact component or frame. Read design context and inspect its screenshot before implementing. If access is denied, report the limitation; do not invent measurements, variable values or exports.
  2. Prefer native SwiftUI/UIKit controls for system behavior. A UI-kit visual does not establish an API's availability or runtime behavior.
  3. Map colors and typography into design tokens and the color system. Preserve semantic roles and all appearance variants instead of scattering literal values.
  4. Use the existing asset generation workflow for project catalogs and Icon Composer guidance for separately editable icon layers. A Figma template alone is not a validated native .icon bundle.
  5. Verify the result with the installed SDK, screenshots, accessibility sizes, dark mode and resizable iPad layouts. Keep untested behaviors explicit.

Free alternative

Figma is optional. Start from the repository's semantic tokens, native SwiftUI/UIKit controls and asset CLI. Build and inspect in Xcode Simulator on a Mac with Xcode. This workflow needs no paid design service or Figma access; see asset generation. Read Apple's online HIG for platform guidance.

Refresh procedure

Reopen Apple's resource page, record which kit links changed, and inspect only the components needed for the requested app. Preserve source provenance and per-resource dates. Do not mark all framework guides current because a design-kit version changed. For installed API documentation, see Xcode documentation resources.

Included editable template

The repository now includes an original app icon layer pack, with Default/Dark/Mono studies, a local interactive preview and manifests accepted by the existing assets CLI. Use the files directly without Figma. The generated catalog is iOS-only; native layered icons and watchOS need the separate Icon Composer/Xcode verification described in the pack.

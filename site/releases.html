October 2, 2026 · on main · npm 2.10.0 and CLI 0.4.1 prepared, not yet released

Audit: what was replaced, and why

After the agent landed, the whole repository and this website were checked for older code and pages that were wrong, out of date or duplicated. Each was replaced, and each fix has a test where code changed.

  • The build budget no longer runs out before you build. The agent’s 25-minute limit used to start when the plan was written, so reading PLAN.md first could use it up. It now starts at the first build. Each refinement now gets its own budget; before, a project could never be built again after 8 attempts.
  • ios-agent clean --help no longer deletes files. It used to run a real clean, and so did a mistyped option. Now every command prints help for --help, unknown options are refused, and clean will not erase a build-agent project’s history.
  • --help no longer runs commands. Before, install-command --help installed a file and preflight --help ran checks. loop status also stopped creating empty folders.
  • Correct install steps. /ios-build pointed at the npm version that does not contain the agent, and said XcodeGen was required. It now gives the working checkout install, and XcodeGen is optional. An old CLI pin (0.2.0) is now 0.4.0.
  • A steadier demo test. The Reading List UI test sometimes typed before the screen was ready. It now waits for each step, always uses the same simulator, and saves screenshots when it fails.
  • One place to choose a workflow. Three guides overlapped on “turn an idea into an app”. One page now picks between the agent, the starter and the loop, and the others point to it.
  • Out-of-date statements removed. The package page said version 2.8.0, that XcodeGen was required and that apps could not be generated. A setup page said integration tools were not on npm, though they shipped in 2.8.0. Xcode 27 pages said the test Mac had Xcode 26.6. Each now states what is true and what is still untested.

October 2, 2026 · on main · repository 3.9.0 and npm 2.10.0 prepared, not yet released

Build an app from one sentence

The new /ios-build command for Claude Code plans an iOS app (screens, data model, every capability it needs and the third-party costs), writes the SwiftUI code and Xcode project, then builds, runs and screenshots it in the simulator, ending with a report of what needs your accounts or money. XcodeGen is optional: the agent can write the Xcode project itself.

Capabilities are modules: 41 of them (Sign in with Apple, SwiftData, StoreKit, MapKit, Swift Charts, widgets and Live Activities, Apple Pay, passkeys and more), out of a catalog of 161. All 41 compiled together with Xcode 27.0 in Swift 6 mode. Four apps the agent planned and wrote, including a food-delivery app with 20 modules, built on the first build and ran in the simulator.

Not yet verified: the agent's own automatic build-and-fix loop on a Mac, each module's individual verify run, and purchases or Live Activities at runtime. The existing loop command keeps its separate job: making an existing project pass your own acceptance tests.

Use the Apple documentation installed with Xcode through its official MCP documentation tool. Bridge access requires Xcode approval, offline behavior is controlled by Xcode, and symbol-level SDK diffs remain unsupported.

Checks and supported configurations →

Local release preparation

Use apple analyze to inspect a target and apple prepare to create an integrity-hashed local draft. The output separates observed facts, inferred candidates and unanswered questions. Unchanged inputs reuse a verified package; changed evidence creates a new package.

npx -y ios-agent-mcp@latest apple analyze --project /path/to/app --target App --configuration Release --json
npx -y ios-agent-mcp@latest apple prepare --project /path/to/app --target App --configuration Release --json

This phase does not connect to Apple, run an AI provider, archive, sign, upload or submit an app. Draft evidence is not a release approval.

Fixes and verification

  • Corrected JSONDecoder/JSONEncoder formatter false positives.
  • 248 MCP tests pass, including 29 launch tests and 52 release-preparation tests.
  • Twelve launch benchmark fixtures include valid and broken configurations, diagnosis/fix checks and unnecessary-change detection. Agent trials for these tasks have not been run.

The previous benchmark stays unchanged: 120 runs, 60/60 passes in each arm, and 60 paired ties. We do not claim measured improvement from this update.

Private reporting remains experimental

The 37th unified tool, private_feedback, requires a configured HTTPS receiver and explicit preview approval. Hosted delivery is not live by default. No silent public submission is added.
